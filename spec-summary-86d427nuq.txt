E2E Pipeline Test 3 — Full Run (spec 86d427nuq)

This specification defines a full end-to-end run of the autoresearch
nonfiction book summarization benchmark pipeline (genre-aware, frozen
booksum-v4). A "full run" exercises every frozen stage — rubric construction,
corpus report, genre-stratified benchmark splits, mock smoke gate, then real
OpenRouter runs across all three splits (chapter_fast, book_gate,
book_holdout) for both 30m and 60m products, followed by judging, leaderboards,
and results verification.

Key points covered:

- Scope: 10 ordered stages from preflight (env + corpus + manifest checks)
  through results.tsv consistency verification. Real runs must record catalog
  and price snapshots and use a judge model; mock runs are the pre-spend gate.

- Frozen contract: only candidate_spec.py is editable; scoring.py, bench/
  splits, data/, rubrics, judge settings, benchmark_version.json, and the
  results.tsv schema are frozen. The test leaves candidate_spec.py at its
  committed baseline.

- Validation rules: per-profile scoring gates (30m → 0.50/0.15; 60m →
  0.60/0.50; default 0.70/0.60), hard-fail criteria (length outside hard
  tolerance, faithfulness/concept-coverage below minimum, malformed output),
  length-control rules (max_passes=5, tolerance vs hard_tolerance,
  edit_existing vs regenerate_from_source), composite score weighting, and
  candidate acceptance/promotion gates.

- State flows: run lifecycle, loading/empty/error/offline states, retry vs
  fail-fast semantics (402 with --wait-for-credits polling, 401/403 abort),
  and resume via checkpoint state.

- API contracts: OpenRouter generation (one model per stage, structured JSON
  summary_response schema requiring summary_md + estimated_visible_words,
  uncached cost accounting), judge contract (five judge fields or
  deterministic fallback), and catalog/price snapshot contract.

- Data models: Profile (70 variants), StageConfig, LengthControlConfig,
  BudgetAllocatorConfig, CandidateSpec, SampleScore, DatasetScore, the frozen
  34-column results.tsv schema, and entity relationships
  (book→chapter→rubric→sample→score→run→results row).

- Edge cases: abort conditions, network/retry, empty/degenerate data
  (zero-chapter books, missing rubrics, empty splits), concurrent edit
  serialization, and cost safety.

- Performance targets, dashboard accessibility requirements (WCAG AA, keyboard
  operability, non-color-only status), and explicit PASS/FAIL acceptance
  criteria for the E2E test (exit 0, populated artifacts, snapshot presence,
  results.tsv rows with non-empty artifact paths and n_genre_macros >= 2,
  leaderboard rendering, no frozen-file modification).

Out of scope: prompt/model optimization, corpus bootstrapping, dashboard
development, re-judging, and benchmark version changes.
